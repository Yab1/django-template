# scaffold_standard_api

Generates the standard REST scaffold using a **package-based API layout** for each resource. CRUD audit endpoints and the full history API surface are generated by default.

- `apis/<resource>/crud.py` — create, list, detail, update, delete, restore, hard delete APIs
- `apis/<resource>/history.py` — history list/detail/previous/next/diff/revert APIs
- `apis/<resource>/audit.py` — object/model CRUD audit APIs
- `apis/<resource>/__init__.py` — re-exports the resource API classes
- `services/<resource>.py` — create, update, delete, restore, hard_delete (+ `revert_to_history` when enabled)
- `selectors/<resource>.py` — list, detail, history list/detail (+ optional selectors for extras)
- `filters.py` — `django_filters.FilterSet` (new file or appended)
- `urls.py` — pattern list (only if `urls.py` is empty)

## Usage

```bash
python manage.py scaffold_standard_api <app_label>.<ModelName> [--url-prefix ...] [--openapi-tag ...]
```

Examples:

```bash
python manage.py scaffold_standard_api security.Policy --dry-run
python manage.py scaffold_standard_api terminology.CodeSystem --full --skip-filters --skip-urls --force
```

## Notes

- App-level `apis/__init__.py` still re-exports the generated classes, so existing `urls.py` import style stays the same.
- If new API classes are added to the base scaffold and do not fit `crud`, `history`, or `audit`, the generator raises an error so grouping stays explicit.
- `urls.py`, `filters.py`, services, and selectors still follow the same behavior as the base scaffold generator.
- For `contenttypes.ContentType` relations, generated input serializers now use natural key strings via `ContentTypeNaturalKeyField` (for example `individuals.practitioner`) instead of raw integer `content_type_id` input values.

## Decimal fields (models → serializers)

The generator mirrors each Django `DecimalField` on the model:

- **Output and input** (including nested `inline_serializer` / array children): `serializers.DecimalField(max_digits=…, decimal_places=…, coerce_to_string=False)` — never `CharField` for decimals.
- **`decimal_places`** comes from the model field (do not hard-code in the generator). Project convention: money and most quantities use **2**; geo coordinates (`longitude`, `latitude`, `altitude`) use **8**.
- **`FloatField`** maps to `serializers.FloatField` (not `CharField`).
- API responses use JSON numbers: set `REST_FRAMEWORK["COERCE_DECIMAL_TO_STRING"] = False` in `config/settings/rest_framework.py` (already the project default).

After scaffolding, confirm model `decimal_places` match the domain (especially money vs clinical precision) before running migrations.
